# v0.0.1-genesis

## Genesis · The unit is the operation.

This is the first public snapshot of Vespi.

It is intentionally small. The purpose of this release is to make the **origin visible before the implementation hardens**.

### What exists

- A bilingual public definition of the problem.
- A provisional operation-first architecture.
- Explicit separation between capability, context, visibility and authority.
- A first model of heterogeneous bodies and bounded authority.
- The initial Stellar flagship direction.
- A public genesis that records both current theses and current non-claims.

### What this release does not claim

This is **not** a production runtime, stable protocol, compliance product or finished multi-agent framework.

The architecture is still being arbitrated in public.

### Why publish this early?

Because the history is part of the evidence.

Vespi should not arrive later with a polished origin story. Specs, rejected ideas, tests, RCs and changes of direction should remain inspectable as they happen.

> **Vespi is being defined in public. This repository records not only what survives, but what gets rejected.**

# v0.0.1-genesis — Español

## Génesis · La unidad es la operación.

Este es el primer corte público de Vespi.

Es deliberadamente pequeño. El objetivo de este release es hacer visible **el origen antes de que la implementación se endurezca**.

### Qué existe

- Una definición pública bilingüe del problema.
- Una arquitectura provisional centrada en la operación.
- Separación explícita entre capability, context, visibility y authority.
- Un primer modelo de cuerpos heterogéneos y authority acotada.
- La dirección inicial del flagship Stellar.
- Un génesis público que registra tanto las tesis actuales como aquello que todavía no afirmamos.

### Qué no afirma este release

Esto **no** es todavía un runtime de producción, un protocolo estable, un producto de compliance ni un framework multiagente terminado.

La arquitectura sigue bajo arbitraje público.

### ¿Por qué publicarlo tan temprano?

Porque la historia también es evidencia.

Vespi no debería aparecer después con un relato de origen perfecto. Specs, ideas rechazadas, tests, RCs y cambios de dirección deben quedar inspeccionables mientras ocurren.
